# Dependencies and desktop builds

`go.mod` pins all direct modules, including Fyne v2.8.2 (released; [upstream](https://github.com/fyne-io/fyne/tree/v2.8.2), BSD-3-Clause), `tcell/v3` v3.6.0, `lipgloss/v2` v2.1.1, and notmutt `lib/xdg` and `lib/localipc` v0.1.0 plus `lib/tui` v0.1.3 (Apache-2.0; independently tagged `lib/tui/v0.1.3`). A `replace` directive builds Fyne from [fishing-agents/fyne](https://github.com/fishing-agents/fyne/tree/fix/wayland-visible-create) `v2.8.2-0.20261001232054-d7b412429937` (BSD-3-Clause): v2.8.1 plus one commit that keeps Wayland windows visible at creation except the systray monitor; neither upstream v2.8.2 nor the fork's default branch contains that fix, so the build does not include upstream's v2.8.2 changes until the fix is rebased. The TUI module provides shared theme resolution, table geometry, tab strip, and status layout; its sole direct dependency is `github.com/mattn/go-runewidth`, selected at v0.0.31 (MIT); existing `github.com/clipperhouse/uax29/v2` stays at v2.7.0. Windows named-pipe I/O uses [Microsoft/go-winio](https://github.com/Microsoft/go-winio) v0.6.4 (MIT): its cancellable `DialPipeContext`, secured `ListenPipe`, and first-instance/remote-rejection behavior replace hand-rolled overlapped Win32 I/O. Its selected graph adds `github.com/sirupsen/logrus` v1.10.2 (MIT). Go 1.26.6 is required. Mihomo is a separately selected executable, not a Go dependency; no core binary is bundled.

Inspect the selected module graph with `go list -m all` and its edges with `go mod graph`. `THIRD_PARTY_LICENSES.txt` contains the license text and notices for every selected module, including Fyne's bundled fonts. The module cache is not vendored. Changes to a direct or transitive pin require a new license/security review, graph comparison, and target build checks. The project maintainer owns upgrades or removal; remove unused dependencies rather than silently changing their versions. The 2026-11-17 upgrade of every module to its latest release was reviewed this way: no license changed, `github.com/ebitengine/purego` v0.11.3 (Apache-2.0, macOS notifications in beeep) and graph-only `github.com/HugoSmits86/nativewebp` v1.3.0 (MIT) were added, and `github.com/jackmordaunt/icns/v3` was removed.

Fyne's native desktop driver requires CGO and platform graphics libraries: Linux needs an X11/OpenGL development toolchain (Mesa, Xcursor, Xrandr, Xinerama, Xi, Xxf86vm) plus Wayland and xkbcommon headers (Debian: `libwayland-dev`, `libxkbcommon-dev`, `wayland-protocols`), because `go-gl/glfw` v3.4 builds both the X11 and Wayland backends when no `x11` or `wayland` build tag is given; macOS needs Xcode Command Line Tools; Windows needs the runner's MinGW/GCC toolchain. Native builds must run on each target; `CGO_ENABLED=0` cross-compilation of the `ci`-tagged software renderer is not a release build. See [Fyne's cross-compilation guide](https://docs.fyne.io/started/cross-compiling/) and [packaging guide](https://docs.fyne.io/started/packaging/). `.github/workflows/build.yml` runs tagged tests/vet and native desktop builds on Linux, macOS, and Windows; it uploads per-platform build artifacts, not signed releases. Local Linux in this workspace lacks graphics headers, so only `-tags ci` software-renderer tests/vet have been run locally; target-native CI results remain a release gate.

## Localization

ClashPulse embeds TOML catalogs and uses `github.com/nicksnyder/go-i18n/v2` v2.7.0 (MIT), which Fyne also requires. Its `Bundle.LoadMessageFileFS` supports build-time embedded files without runtime catalog reads. `github.com/jeandeaual/go-locale` v0.0.0-20250612000132-0ef82f21eade (MIT) supplies cross-platform system locale detection; `golang.org/x/text` v0.44.0 and `github.com/BurntSushi/toml` v1.6.0 were already in the selected graph. These existing pins are now direct imports; no new version or transitive package was introduced. `references/notmutt/src/i18n` demonstrates the embedded go-i18n pattern at v2.6.1 but is not vendored into ClashPulse. The maintainer owns catalog review and future upgrades alongside Fyne; remove the direct localization imports when this interface language support is removed.

## Optional managed data

`examples/resources.toml` seeds four MetaCubeX/meta-rules-dat sources enabled by default: `geoip.dat`, `geosite.dat`, `Country.mmdb`, and the domain-format `cn.mrs` rule-set. The client downloads them during validated profile refresh/activation or explicit resource refresh; `download subscription` remains profile-only. Downloading `cn.mrs` does not add a filter or DNS route. No source bytes are bundled. The exact previous disabled seed is migrated once; customized resource files are never replaced. Users can disable or replace each source. The ClashPulse maintainer owns review of availability, provenance, updates, and removal or replacement.

[MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) publishes and updates these release assets (repository license: GPL-3.0). Recorded upstream inputs include [Loyalsoldier/geoip](https://github.com/Loyalsoldier/geoip) (CC-BY-SA-4.0), [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) (MIT), and [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script) (GPL-2.0). These provenance and license identifiers do not establish that composite data has one uniform license or grant downstream redistribution rights; review the actual data and upstream terms before redistributing it.

The enabled `releases/download/latest` URLs are mutable and have no static SHA-256 pin. A current release digest is metadata for that release only: hardcoding it against a moving URL would break future updates unless the release URL is frozen too. The maintainer must review source provenance and integrity when updating these URLs; users who need a fixed digest can select a versioned asset and pin its matching digest.

The `cn` rule-set URL comes from [MetaCubeX's documented Mihomo rule-set example](https://github.com/MetaCubeX/meta-rules-dat/blob/master/README.md). Its `meta` branch is mutable and unpinned; the upstream README says `geosite:cn` incorporates [blackmatrix7/ios_rule_script's ChinaMax domain list](https://github.com/blackmatrix7/ios_rule_script/tree/master/rule/Clash/ChinaMax). The default downloads only the declared MRS bytes; a `RULE-SET` filter needs a target from the active profile, or a DNS route needs an explicit resolver set. Neither is enabled by the seed.
