# Dependencies and desktop builds

`go.mod` pins all direct modules, including Fyne v2.8.1 (released; [upstream](https://github.com/fyne-io/fyne/tree/v2.8.1), BSD-3-Clause), `tcell/v3` v3.4.2, `lipgloss/v2` v2.0.5, and notmutt `lib/xdg` and `lib/localipc` v0.1.0 plus `lib/tui` v0.1.0 (Apache-2.0; independently tagged `lib/tui/v0.1.0`). The TUI module provides shared theme resolution, table geometry, tab strip, and status layout; its sole direct dependency is `github.com/mattn/go-runewidth` v0.0.27 (MIT, upgraded from v0.0.24); existing `github.com/clipperhouse/uax29/v2` stays at v2.7.0. Windows named-pipe I/O uses [Microsoft/go-winio](https://github.com/Microsoft/go-winio) v0.6.2 (MIT): its cancellable `DialPipeContext`, secured `ListenPipe`, and first-instance/remote-rejection behavior replace hand-rolled overlapped Win32 I/O. Its selected graph adds `github.com/sirupsen/logrus` v1.9.3 (MIT). Go 1.26.6 is required. Mihomo is a separately selected executable, not a Go dependency; no core binary is bundled.

Inspect the selected module graph with `go list -m all` and its edges with `go mod graph`. `THIRD_PARTY_LICENSES.txt` contains the license text and notices for every selected module, including Fyne's bundled fonts. The module cache is not vendored. Changes to a direct or transitive pin require a new license/security review, graph comparison, and target build checks. The project maintainer owns upgrades or removal; remove unused dependencies rather than silently changing their versions.

Fyne's native desktop driver requires CGO and platform graphics libraries: Linux needs an X11/OpenGL development toolchain (Mesa, Xcursor, Xrandr, Xinerama, Xi, Xxf86vm); macOS needs Xcode Command Line Tools; Windows needs the runner's MinGW/GCC toolchain. Native builds must run on each target; `CGO_ENABLED=0` cross-compilation of the `ci`-tagged software renderer is not a release build. See [Fyne's cross-compilation guide](https://docs.fyne.io/started/cross-compiling/) and [packaging guide](https://docs.fyne.io/started/packaging/). `.github/workflows/build.yml` runs tagged tests/vet and native desktop builds on Linux, macOS, and Windows; it uploads per-platform build artifacts, not signed releases. Local Linux in this workspace lacks graphics headers, so only `-tags ci` software-renderer tests/vet have been run locally; target-native CI results remain a release gate.

## Optional managed data

`examples/resources.toml` catalogs MetaCubeX/meta-rules-dat `geoip.dat`, `geosite.dat`, and `Country.mmdb` release assets plus its domain-format `cn.mrs` rule-set. ClashPulse supports managed `dat` files for geoip/geosite and `mmdb` for Country, plus `yaml`, `text`, and `mrs` rule-set/rule-provider sources. Catalog entries are disabled, refresh at 24-hour intervals only when enabled, and bundle no source bytes; loading the catalog does not download anything. Users may replace a source URL or leave/turn off its entry. The ClashPulse project maintainer owns review of source availability, updates, provenance, and removal or replacement.

[MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) publishes and updates these release assets (repository license: GPL-3.0). Recorded upstream inputs include [Loyalsoldier/geoip](https://github.com/Loyalsoldier/geoip) (CC-BY-SA-4.0), [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) (MIT), and [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script) (GPL-2.0). These provenance and license identifiers do not establish that composite data has one uniform license or grant downstream redistribution rights; review the actual data and upstream terms before redistributing it.

The `releases/download/latest` URLs are mutable and have no static SHA-256 pin. A current release digest is metadata for that release only: hardcoding it against a moving URL would break future updates unless the release URL is frozen too. The maintainer must review release provenance and integrity when updating or enabling sources; users who need a fixed digest should select a versioned asset and pin its matching digest.

The disabled `cn` rule-set URL comes from [MetaCubeX's documented Mihomo rule-set example](https://github.com/MetaCubeX/meta-rules-dat/blob/master/README.md). Its `meta` branch is mutable and unpinned; the upstream README says `geosite:cn` incorporates [blackmatrix7/ios_rule_script's ChinaMax domain list](https://github.com/blackmatrix7/ios_rule_script/tree/master/rule/Clash/ChinaMax). Enabling downloads only the declared MRS bytes; a `RULE-SET` filter needs a target from the active profile, or a DNS route needs an explicit resolver set. Neither is enabled by the seed.
